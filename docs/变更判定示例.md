# 变更判定示例：6 个变更的主版本 / 次版本判定

- 对应文档：《SOP 模板版本发布流程》第 1 节版本号规则
- 文档版本：1.0；交付日期：2026-11-25
- 全部示例均为虚构数据，不含真实个人信息、企业信息与客户名称；模板名与角色名均为虚构的通用名称。
- 判定方法：先看是否命中主版本三条（M1 增删步骤、M2 调整顺序、M3 更换负责角色），命中任一条即主版本；否则看是否命中次版本四条（m1 SLA、m2 表单字段、m3 操作说明、m4 文字修订）；无法判定的提交评审会裁定，裁定前按主版本处理。

## 例 1：新增执行步骤 → 主版本

- **模板**：会员入会办理，现行版本 2.3
- **变更内容**：在原第 2 步之后新增一步「核验企业营业执照有效期」；其余步骤内容不变，步骤编号顺延。
- **适用规则**：M1（增删步骤）。
- **判定**：**主版本**，新版本 **3.0**。
- **推理**：
  1. 变更是在模板正文中增加一个编号执行步骤，属于规则 M1 列明的“增删步骤”。
  2. 规则 M1 不设数量下限：增加 1 个步骤与增加多个步骤同样触发主版本。
  3. 其余步骤内容不变、仅编号顺延不影响判定——触发条件是“新增步骤”本身。
  4. 因此按第 1.2 节记主版本 +1，次版本归零：2.3 → 3.0。
  5. 后续流程：主版本变更必须经过试运行（1 个会所、至少 2 周；累计 20 个实例后进入达标评估；4 周不足 20 个实例时由 SOP 负责人裁定延长 2 周或按现有样本裁定），达标后方可正式发布。

## 例 2：调整步骤顺序 → 主版本

- **模板**：续约提醒，现行版本 2.3
- **变更内容**：将「发送续约提醒」步骤由第 5 步移到第 3 步；步骤本身的内容、负责角色均不变。
- **适用规则**：M2（调整步骤顺序）。
- **判定**：**主版本**，新版本 **3.0**。
- **推理**：
  1. 变更只移动了一个步骤的位置，步骤内容与负责角色均未变，但执行先后顺序发生了变化，属于规则 M2 列明的“调整步骤顺序”。
  2. 顺序变化会改变执行者实际拿到任务的时间点与前置条件，属于流程结构变化。
  3. 因此按第 1.2 节记主版本 +1：2.3 → 3.0。
  4. 后续流程：主版本变更必须经过试运行，达标后方可正式发布。

## 例 3：更换步骤的负责角色 → 主版本

- **模板**：投诉处理，现行版本 2.3
- **变更内容**：「初步登记」步骤的负责角色由「前台接待」改为「值班经理」；步骤内容、顺序均不变。
- **适用规则**：M3（更换步骤的负责角色）。
- **判定**：**主版本**，新版本 **3.0**。
- **推理**：
  1. 变更只换了「初步登记」这一步的负责角色（RACI 中的 R），属于规则 M3 列明的“更换步骤的负责角色”。
  2. 负责角色变化会改变任务的实际承接人与执行能力要求，属于流程结构变化。
  3. 注意区分：仅更换被咨询角色（C）或被告知角色（I）不算结构变化；本例换的是 R，故触发 M3。
  4. 因此按第 1.2 节记主版本 +1：2.3 → 3.0。
  5. 后续流程：主版本变更必须经过试运行，达标后方可正式发布。

## 例 4：SLA 变化 → 次版本

- **模板**：场地预订确认，现行版本 2.3
- **变更内容**：SLA 从「2 小时内回复」改为「4 小时内回复」；步骤不增删、不换序、不换负责角色。
- **适用规则**：m1（SLA 变化）。
- **判定**：**次版本**，新版本 **2.4**。
- **推理**：
  1. 先核对主版本三条：无新增或删除步骤（不命中 M1）；步骤顺序不变（不命中 M2）；负责角色不变（不命中 M3）。故不是主版本。
  2. SLA 变化属于规则 m1 列明的次版本情形：不改结构但影响执行。
  3. 因此按第 1.3 节记次版本 +1：2.3 → 2.4。
  4. 后续流程：次版本变更可跳过试运行，评审通过后直接正式发布。

## 例 5：表单新增必填字段 → 次版本

- **模板**：活动报名，现行版本 2.3
- **变更内容**：报名表单新增必填字段「参与人数」；步骤不增删、不换序、不换负责角色。
- **适用规则**：m2（表单字段变化）。
- **判定**：**次版本**，新版本 **2.4**。
- **推理**：
  1. 先核对主版本三条：表单字段不是编号执行步骤，增字段不等于增步骤（不命中 M1）；步骤顺序不变（不命中 M2）；负责角色不变（不命中 M3）。故不是主版本。
  2. 表单字段变化属于规则 m2 列明的次版本情形：不改结构但影响执行（执行者须多填一项，会影响实例耗时与完整率口径）。
  3. 因此按第 1.3 节记次版本 +1：2.3 → 2.4。
  4. 后续流程：次版本变更可跳过试运行，评审通过后直接正式发布。

## 例 6：错别字与失效链接修正 → 次版本（文字修订）

- **模板**：入会指引，现行版本 2.3
- **变更内容**：修正正文两处错别字，并修正一条失效的内部链接；步骤、顺序、负责角色、SLA、表单、操作说明均不变。
- **适用规则**：m4（文字修订）。
- **判定**：**次版本**，标注「文字修订」，新版本 **2.4**。
- **推理**：
  1. 先核对主版本三条：无一命中，故不是主版本。
  2. 错别字与失效链接修正不影响执行，属于规则 m4 列明的“错别字、链接修正等不影响执行的修改”。
  3. 规则 m4 明确规定此类修改“也记次版本，并在变更记录中标注『文字修订』”：不是不升版本，而是升次版本 + 标注。
  4. 因此按第 1.3 节记次版本 +1：2.3 → 2.4，变更记录标注「文字修订」。
  5. 后续流程：次版本变更可跳过试运行，评审通过后直接正式发布。

## 一致性说明

- 6 个示例覆盖主版本三条规则各 1 例（M1、M2、M3），次版本四条规则中的 3 条（m1、m2、m4）；m3（操作说明变化）未单独举例——因操作说明变化的判定逻辑与 m1、m2 相同（不改结构但影响执行），且例 5 的表单字段变化已覆盖“影响执行但不改结构”这一类。
- 6 例均从现行版本 2.3 起算，判定结果与第 1 节规则逐条对应，无例外、无自相矛盾之处。
- 判定边界：例 3 与“仅更换 C/I 角色”的区分、例 5 与“增步骤”的区分，已在各自推理第 2–3 步中写明。
